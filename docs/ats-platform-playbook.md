# Verity Playbook: Workday, Greenhouse, Career Switches, and GitHub

> **Use this guide to improve the clarity and parseability of a truthful resume. It does not promise a job, interview, ranking, or automated-system pass.**

## 1. The right goal: maximize parseability, not “beat” an ATS

The practical goal is to submit a concise, job-specific resume that a candidate portal can extract reliably and a recruiter can understand quickly. Workday allows candidates to reuse a prior application or upload a new resume or CV, while its talent-acquisition product describes deriving skills from resumes. Greenhouse’s candidate experience uses the most recently uploaded resume by default and lets the candidate replace it. These platform behaviors make a dedicated, role-specific resume version worthwhile for every materially different job target. [1] [2] [3]

| Do | Avoid |
| --- | --- |
| Use a tailored DOCX as the primary upload where the employer accepts it; keep a matching PDF as a backup. | Assuming a PDF, DOCX, or any other format is guaranteed to parse identically for every employer configuration. |
| Use one clear text column, conventional headings, readable fonts, and plain bullets. | Text boxes, decorative sidebars, tables for core experience, image-only content, icons in place of text, and résumé “infographics.” |
| Name skills using the language of the job description **only where genuinely supported**. | Keyword stuffing or turning a related capability into a claimed qualification. |
| Review every autofilled field and manually correct it before submitting. | Treating parsed application fields as automatically accurate. |
| Create a separate tailored version per target role and keep the master resume unchanged. | Reusing a generic resume for unrelated roles or overwriting the master source. |

## 2. Workday upload checklist

Workday supports a new resume upload as part of its candidate workflow and may derive skills from resume content. Treat the application form as part of the resume, not as an afterthought. [1] [2]

| Step | What to do in Verity | What to check in Workday |
| --- | --- | --- |
| 1. Select the target | Paste the exact job description and set the target title/company. | Confirm the requisition title, location, work authorization, and required questions. |
| 2. Produce an ATS-safe version | Choose a restrained template; use standard sections such as **Summary**, **Skills**, **Experience**, and **Education**. | Upload the tailored DOCX first if accepted; retain the PDF for recruiters who request it. |
| 3. Check evidence | Review Exact, Semantic, Related, and Gap tiers. Keep related skills visibly distinct. | Make sure skills, employers, dates, and education populate correctly in every form field. |
| 4. Resolve gaps honestly | Add a supported project, achievement, or credential only when it is real and verifiable. | Do not add an unsupported competency just because the job has a matching field. |
| 5. Final quality gate | Run Verity’s quality gate, then prepare the final export. | Read the full application before submission; correct contact details, chronology, and any malformed parsing. |

**Recommended Workday conventions:** write dates consistently, place employer and job title in normal text, and use an explicit skills section. If the application asks for work history or education again, complete those fields carefully even when the resume appears to have populated them.

## 3. Greenhouse upload checklist

Greenhouse advises that the most recently uploaded resume is used by default and can be replaced. Before sending a substantially different application, replace the uploaded document with the tailored version for that role. Greenhouse also advises that an application email cannot be changed after submission, so the final review should include contact information. [3]

| Step | What to do in Verity | What to check in Greenhouse |
| --- | --- | --- |
| 1. Match the role | Paste the exact posting and run analysis before creating the version. | Confirm that the job title and location match the document you prepared. |
| 2. Create a dedicated variant | Save a named version, for example `Business-Analyst_Acme_2026-08`. | Replace the previous upload if this is a new career path or job family. |
| 3. Keep structure predictable | Use a text-first DOCX or PDF with conventional labels. | Check the resume preview or parsed fields if the portal presents them. |
| 4. Complete application fields | Keep the same dates, employer names, and degree details as the tailored resume. | Validate email address, phone number, work authorization, and voluntary disclosure responses before submitting. |
| 5. Preserve traceability | Keep the version, original job description, and evidence map in Verity. | Record the application date and the exact resume version used. |

## 4. Step-by-step career-switch example using Verity

This is an **illustrative** transition from customer operations to a junior business analyst role. It demonstrates how to improve relevance without inventing SQL, dashboarding, experimentation, or any other skill not present in the source material.

### Source resume evidence

| Source section | Truthful source content |
| --- | --- |
| Summary | “Customer Operations Coordinator with four years of experience supporting service teams and improving internal workflows.” |
| Experience bullet 1 | “Built an Excel tracker used by the support team to monitor weekly case volume and response times.” |
| Experience bullet 2 | “Compiled recurring issue themes from customer escalations and shared findings with product and operations leaders.” |
| Experience bullet 3 | “Coordinated a process update that reduced duplicate customer follow-ups.” |
| Skills | Excel, customer operations, stakeholder communication, process documentation. |

### Target role: Junior Business Analyst

Assume the job description asks for Excel, stakeholder communication, reporting, process improvement, SQL, dashboard tools, business requirements, and experience working with product teams.

### Step 1 — Load the facts

Paste the source resume into **Your master resume**. Paste the full job description into **Target job description**. Set the target title to **Junior Business Analyst** and the company to the employer’s name. Do not edit the master resume to imitate the new role.

### Step 2 — Read the evidence map correctly

| Job requirement | Expected Verity tier | Correct interpretation |
| --- | --- | --- |
| Excel | Exact Match | The source explicitly names Excel and an Excel tracker. It may appear in the tailored resume. |
| Stakeholder communication | Exact or Curated Semantic Match | The source says findings were shared with product and operations leaders. It may be described accurately. |
| Reporting / analysis | Related Skill | The source supports tracking and issue-theme compilation. Do not call this advanced analytics unless the source proves it. |
| Process improvement | Exact or Related Skill | The reduced duplicate follow-ups support an operational-process achievement. |
| Product collaboration | Related Skill | Sharing findings with product leaders supports collaboration, not product-management ownership. |
| SQL and BI dashboards | Insufficient Evidence | These remain gaps unless the candidate has real, supportable experience or a genuine project to add. |

### Step 3 — Use only supported tailoring controls

Choose a concise, professional tone and a one-page layout when the experience level fits. Keep the professional summary and projects sections enabled only if the candidate has truthful content for them. Use **Balanced** keyword optimization, not maximum coverage, when several requirements are unsupported.

### Step 4 — Accept a grounded rewrite, not a title rewrite

**Weak and inaccurate version:**

> Business Analyst experienced in SQL, dashboard development, requirements gathering, and product analytics.

This is inaccurate because the source material did not support SQL, dashboards, formal requirements gathering, or product analytics.

**Grounded version Verity should allow:**

> Customer operations professional with four years of experience using Excel to monitor service trends, documenting workflows, and communicating recurring customer issues to product and operations stakeholders.

**Grounded experience bullets:**

> - Built and maintained an Excel tracker that helped the support team monitor weekly case volume and response times.
> - Consolidated recurring customer-escalation themes and shared findings with product and operations leaders to inform workflow discussions.
> - Coordinated a process update that reduced duplicate customer follow-ups.

These bullets sharpen the analytical and operational relevance of the original source without changing the candidate’s job title or claiming unsupported tools.

### Step 5 — Turn gaps into an ethical action list

Verity’s gap suggestion should read: **“Your resume does not show SQL or BI dashboard experience. Add a course, portfolio project, or prior work example only if it is genuine and you can discuss it.”**

The candidate might complete a real SQL project, publish it on GitHub, and add it to the resume only after it exists. Until then, the honest choice is to leave the gap visible and focus on the strongest transferable evidence.

### Step 6 — Export and submit

Run the final quality gate. If it passes, prepare the document in DOCX for primary upload and retain the equivalent PDF. In the portal, inspect all autofilled fields and ensure the dates, employers, job title, degree, email, and phone number are correct. The resume should be tailored, but the application form must remain internally consistent.

## 5. Making Verity stand out on your GitHub profile

Treat the repository as a product case study rather than a folder of code. The strongest GitHub presentation makes the problem, safety model, architecture, and proof of implementation easy to understand in under two minutes.

| GitHub element | Recommended implementation |
| --- | --- |
| Repository name | Use a clear name such as `verity-ats-resume-builder`. |
| Repository description | “Evidence-first AI resume tailoring with claim traceability, ATS-readiness checks, and quality-gated exports.” |
| Pinned repository | Pin Verity first if it is your best product-quality project. |
| README opening | Lead with the candidate problem and Strict Truth Mode—not generic technology claims. |
| Visual proof | Add 3–5 real screenshots: source intake, match tiers, score breakdown, Truth Guard, and export gate. Never show real candidate data without permission. |
| Architecture | Include a compact diagram of the React client, tRPC API, rules engine, structured AI layer, and database. |
| Feature list | Highlight four-tier matching, evidence citations, safe career-transition suggestions, quality gate, and DOCX/PDF export. |
| Technical credibility | State the stack, database model, test commands, and limitations. Include what you deliberately do **not** claim, such as a guaranteed ATS pass. |
| Demo | After publishing through the project interface, add the live URL near the top of the README. |
| Topics | Add relevant topics such as `react`, `typescript`, `ai`, `resume-builder`, `ats`, `trpc`, `drizzle-orm`, `tailwindcss`, and `career-tech`. |

### Suggested GitHub profile blurb

> Built **Verity**, an evidence-first AI resume optimization workspace. It helps candidates tailor resumes to job descriptions while preserving source truth through claim-level citations, explainable match tiers, and an export quality gate.

### Suggested README demonstration sequence

1. Show the source resume and job-description intake screen.
2. Explain the four evidence tiers with one exact match, one related skill, and one genuine gap.
3. Show the before-and-after resume comparison with cited source evidence.
4. Show the quality gate and explain why it blocks unsupported claims.
5. Provide setup instructions, the testing commands, and a short limitations section.

Do not claim that Verity “beats Workday,” “guarantees interviews,” or “passes every ATS.” The more compelling portfolio story is that it solves a genuine candidate problem responsibly: it makes tailoring systematic while refusing to fabricate qualifications.
